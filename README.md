# EditorStudio · консоль API ИС «Метафора»

Локальное веб-приложение для работы журнала с [ИС «Метафора»](https://metafora.rcsi.science) (РЦНИ) через API v2: загрузка XML и PDF статей, контроль обработки, просмотр метаданных, подписание публикаций, поиск по DOI и EDN.

Консоль работает в двух режимах и выбирает нужный сама:

| Режим | Где | Ключ |
|---|---|---|
| **Сайт** | <https://editorstudio.ru/metafora/> | Каждый вводит ключ своей организации на странице. Ключ хранится только в браузере и отправляется только в «Метафору», сервера у сайта нет. |
| **Локально** | `python server.py` → <http://127.0.0.1:8765> | Ключ лежит в `.env` на вашем компьютере, локальный сервер подставляет его сам, а в браузер ключ не попадает. |

На том же сайте по адресу <https://editorstudio.ru/doaj/> работает [DOAJ Metadata Studio](https://github.com/tsentavta/doajmds). Как устроена сборка, описано в [разделе 14](#14-сайт-editorstudioru).

## 1. Что нужно

- **Python 3.9 или новее.** Сторонние библиотеки не нужны. Проверка: `python --version`.
- **Учётная запись организации в ИС «Метафора»** с правами на ваши журналы.
- **API-ключ** из личного кабинета «Метафоры» (см. [раздел 3](#3-api-ключ)).
- **Браузер:** любой современный (Chrome, Edge, Firefox, Яндекс).

## 2. Установка

```bash
git clone https://github.com/tsentavta/editorstudio.git
cd editorstudio
copy .env.example .env
```

На macOS и Linux вместо `copy` используйте `cp`.

## 3. API-ключ

1. Войдите в [ИС «Метафора»](https://metafora.rcsi.science) под учётной записью организации.
2. В личном кабинете сгенерируйте API-ключ и скопируйте его.
3. Откройте файл `.env` в папке проекта и впишите ключ:

   ```
   METAFORA_API_KEY=ваш_ключ
   ```

4. Сохраните файл и перезапустите сервер, если он уже был запущен.

Ключ привязан к организации. Через него видны только её журналы и публикации, а загружать можно только в журналы, на которые у организации есть права.

> Файл `.env` закрыт в `.gitignore` и в репозиторий не попадает. Не пересылайте ключ по почте и в чатах. Если ключ мог утечь, выпустите в личном кабинете новый и замените его в `.env`.

## 4. Запуск

**Windows:** дважды щёлкните `start.bat`. Откроется окно сервера, а браузер сам откроет страницу.

**Любая система:**

```bash
python server.py
```

Затем откройте в браузере <http://127.0.0.1:8765>.

Другой порт задаётся так: `python server.py --port 9000`.

Сервер работает, пока открыто его окно. Остановить его можно клавишами `Ctrl+C` или закрыв окно.

**Первая проверка.** Нажмите **«Проверить связь»** в правом верхнем углу:

| Индикатор | Что значит |
|---|---|
| 🟢 ключ работает | Всё в порядке |
| 🔴 ключ неактивен | Ключ отключён в «Метафоре» (HTTP 401) |
| 🔴 ключ отклонён | Ключ неверный (HTTP 403) |
| 🔴 нет ключа | В `.env` не задан `METAFORA_API_KEY` |
| 🔴 нет связи | Нет интернета или «Метафора» недоступна |

## 5. Интерфейс

- **Вверху вкладки:** Загрузка, Файлы, Публикации, Поиск.
- **Слева формы,** справа тёмная панель **«Ответ API»**. В ней виден точный запрос, код ответа, время и JSON ответа с подсветкой.
- **Журнал** под панелью хранит последние 100 запросов. Щелчок по строке показывает её ответ снова, а кнопка **«копировать»** копирует JSON. Это удобно, если нужно написать в поддержку.
- **На узком экране** панель ответа переезжает под формы.

## 6. Загрузка статей

Вкладка **«Загрузка»**.

### Выбор формата

| Формат | Когда использовать | Что отправляется |
|---|---|---|
| **Journal XML** | XML выпуска в формате РИНЦ (`journal3.xsd`) | Один XML на весь выпуск или на одну статью |
| **JATS XML** | Статья в JATS 1.4 Archiving (корневой элемент `<article>`) | Только XML, PDF можно догрузить позже |
| **JATS XML + PDF** | Статья в JATS вместе с PDF | XML и PDF одним запросом |

### Порядок действий

1. Выберите формат.
2. Перетащите XML в поле **«XML-файл»** или щёлкните по нему и выберите файл. Для режима JATS + PDF так же добавьте PDF.
3. Поле **«Издательская платформа»** заполнять не обязательно.
4. Нажмите **«Загрузить»**.

Если «Метафора» приняла файл, появится его идентификатор `file_uid`, а ниже карточка **«Обработка»** со шкалой этапов:

```
ЗАГРУЖЕН  →  ОБРАБАТЫВАЕТСЯ  →  ОБРАБОТАН
                               (или ОШИБКА)
```

Статус проверяется автоматически каждые 3 секунды. Когда файл обработан, в карточке появится список созданных статей (`article_uid`) со ссылками **«открыть →»**.

### Проверки при загрузке

«Метафора» проверяет файл на нескольких уровнях:

1. **Форма запроса:** приложен ли файл.
2. **Схема XSD:** для Journal это `journal3.xsd`, для JATS это `JATS-archive-oasis-article1-4.xsd`.
3. **Обязательные данные.** Например, для Journal обязателен диапазон страниц `<pages>`, для JATS обязательны `article-title` и фамилии авторов.
4. **Принадлежность журнала:** ISSN, eISSN и название в XML должны совпадать с журналами вашей организации.
5. **Дубликаты:** повторная загрузка того же XML отклоняется, а в сообщении будет ссылка на уже загруженный файл.

Ошибки схемы выводятся построчно, с номером строки XML. Это сокращает поиск ошибки.

## 7. Файлы

Вкладка **«Файлы»**.

- **Статус.** Вставьте `file_uid` (поле подсказывает uid из истории) и нажмите **«Статус»**. Вы увидите статус XML, наличие PDF и список статей.
- **PDF к файлу.** Нажмите «Выбрать PDF», затем «Загрузить PDF». Работает, только если из XML создана **одна** статья. Если статей несколько, PDF загружается к каждой публикации отдельно (см. [раздел 8](#8-публикации-и-подписание)).
- **Удаление.** «Удалить файл и публикации» удаляет XML и все созданные из него публикации. Это необратимо, поэтому приложение спросит подтверждение. Удалить можно только обработанный файл (статус «Обработан»), у которого нет подписанных публикаций.
- **История загрузок.** Всё, что вы загружали в этом браузере, с последним известным статусом. Щелчок по имени файла открывает его. История хранится только в браузере: на другом компьютере её не будет. Кнопка «Очистить» стирает только локальный список, файлы в «Метафоре» не затрагиваются.

## 8. Публикации и подписание

Вкладка **«Публикации»**.

### Карточка публикации

Вставьте `article_uid` и нажмите **«Открыть»**. Показывается:

- **Языки:** переключатель **RUS / ENG / …** по языкам публикации.
- **Выходные данные:** название, DOI, EDN, год, том, номер, страницы, тип, УДК, даты поступления, принятия и публикации.
- **Авторы:** аффилиации, ORCID, SPIN, Scopus ID.
- **Содержание:** аннотация, ключевые слова, финансирование.
- **Список литературы:** раскрывается по щелчку.
- **Статус подписи:** «подписана» с датой или «не подписана».

По этой карточке удобно проверить, что «Метафора» прочитала XML так, как задумано: нет ли потерянных авторов, разорванной литературы или пустой аннотации на английском.

### PDF к публикации

«Выбрать PDF», затем «Загрузить PDF». К подписанной публикации PDF загрузить нельзя: сначала нужно отозвать подпись.

### Подписание

- **«Подписать публикацию»** подтверждает публикацию от имени организации. Перед подписанием проверьте метаданные и загрузите PDF.
- **«Отозвать подпись»** снимает подпись, например чтобы заменить PDF.

Оба действия спрашивают подтверждение.

### Статусы сразу для многих статей

В блоке **«Статусы подписания»** вставьте до 100 `article_uid`, по одному на строку или через запятую. Таблица покажет дату подписания и дату отзыва. Строка «не найдена или недоступна» означает, что такой публикации нет или она принадлежит другой организации.

## 9. Поиск

Вкладка **«Поиск»**.

- **DOI:** можно вставлять в любом виде, `10.18469/…`, `https://doi.org/10.18469/…` или `doi: 10.18469/…`. Приложение само уберёт префикс.
- **EDN:** шесть символов, регистр не важен.
- **«Искать по всем организациям»** (`public=true`): поиск по всей системе, а не только по вашим публикациям. Полезно, чтобы проверить, не загружена ли статья кем-то ещё.

Найденная публикация показывается с `article_uid`, статусом подписи, наличием PDF и ссылкой на исходный файл.

## 10. Типовые сценарии

### Выпуск журнала в формате РИНЦ (Journal XML)

1. **Загрузка:** формат **Journal XML**, файл XML выпуска, «Загрузить».
2. Дождитесь статуса **«Обработан»**. В карточке появится список статей.
3. Откройте каждую статью («открыть →»):
   - проверьте метаданные на RUS и ENG;
   - загрузите PDF этой статьи. Сверяйтесь по DOI и страницам, чтобы не перепутать файлы.
4. Подпишите каждую публикацию.
5. Контроль: соберите все `article_uid` в блок **«Статусы подписания»** и убедитесь, что подписаны все.

### Одна статья в JATS с PDF

1. Формат **JATS XML + PDF**, оба файла, «Загрузить».
2. После обработки откройте статью, проверьте её и подпишите.

### Замена PDF у подписанной статьи

1. Публикации: откройте статью, «Отозвать подпись».
2. Загрузите новый PDF.
3. Подпишите снова.

### Исправление XML после загрузки

1. Если публикации подписаны, отзовите подписи.
2. Файлы: «Удалить файл и публикации».
3. Загрузите исправленный XML заново.

## 11. Ошибки и что с ними делать

Ошибка показывается в карточке красной плашкой: текст, HTTP-код и машинный код. Полный ответ виден в панели справа.

| Код | Ошибка | Что делать |
|---|---|---|
| 401 | Ключ неактивен | Активируйте или выпустите ключ в личном кабинете |
| 403 | `INVALID_API_KEY` / нет прав на журнал | Проверьте ключ в `.env` и права организации на журнал |
| 404 | Журналы не найдены | ISSN или название журнала в XML не совпадает с журналами организации |
| 404 | `FILE_NOT_FOUND`, `PUBLICATION_NOT_FOUND` | uid неверный или принадлежит другой организации |
| 409 | `XML_ALREADY_EXISTS` | Такой XML уже загружен: перейдите по ссылке на существующий файл |
| 409 | PDF уже существует / публикация уже подписана | Для замены PDF сначала отзовите подпись |
| 409 | Файл содержит подписанные публикации | Отзовите подписи, затем удаляйте |
| 422 | `SCHEMA_ERROR` | XML не проходит XSD: смотрите номер строки в сообщении |
| 422 | `MISSING_REQUIRED_DATA` | Не хватает обязательных полей: они перечислены списком |
| 422 | `MULTIPLE_PUBLICATIONS_FOR_XML` | В XML несколько статей: загружайте PDF к каждой публикации |
| 422 | Файл не обработан | Удалять можно только обработанный файл |
| 500 | `LOCAL_NO_API_KEY` | Не задан ключ в `.env` |
| 502 | `LOCAL_UPSTREAM_ERROR` | Нет связи с «Метафорой»: проверьте интернет и повторите |

Если ошибка непонятна, нажмите «копировать» в панели ответа и отправьте JSON в поддержку «Метафоры». **Ключ в ответах не содержится.**

## 12. Безопасность

- **Ключ на сайте:** хранится в `sessionStorage` (до закрытия вкладки) или, с галочкой «запомнить», в `localStorage` этого браузера. Отправляется только в заголовке `Api-Key` на `metafora.rcsi.science`. На общем компьютере не ставьте галочку и нажимайте «Забыть ключ» после работы.
- **Ключ локально:** хранится только в `.env` на вашем компьютере. Сервер подставляет его в заголовок `Api-Key`, а страница в браузере его не получает.
- **Чужой ключ не выкладывайте:** локальный `server.py` с вашим `.env` нельзя публиковать в интернете, иначе любой посетитель будет действовать от имени вашей организации. Для общего доступа есть сайт, где каждый работает со своим ключом.
- **Сеть:** сервер слушает только `127.0.0.1`, поэтому с других компьютеров сети он недоступен.
- **Запросы:** через сервер можно обращаться только к `/api/v2/*` «Метафоры».
- **Необратимые действия** (удаление, подписание, отзыв подписи) выполняются только после подтверждения в диалоге.
- **Репозиторий:** `.env` закрыт в `.gitignore`. Перед коммитом убедитесь, что `git status` его не показывает.

## 13. Устройство проекта

```
editorstudio/
├── server.py        локальный сервер: статика + прокси к API с ключом
├── start.bat        запуск в Windows (сервер + браузер)
├── .env.example     образец настроек
├── .env             ваш ключ (не в git)
├── static/          консоль «Метафоры» (на сайте — /metafora/)
│   ├── index.html   разметка
│   ├── app.css      стиль
│   └── app.js       логика: режимы, вызовы API, журнал, вкладки
├── site/            стартовая страница сайта, robots.txt, sitemap.xml, 404
├── tools/
│   └── build_site.py   сборка сайта editorstudio.ru
└── .github/workflows/
    └── pages.yml    сборка и публикация на GitHub Pages
```

Настройки в `.env`:

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `METAFORA_API_KEY` | API-ключ организации | — (обязательно) |
| `METAFORA_BASE` | адрес «Метафоры» | `https://metafora.rcsi.science` |

Обе переменные можно задать и через окружение. Переменная окружения важнее `.env`.

Описание API: <https://metafora.rcsi.science/api_doc>, спецификация OpenAPI: `/api/v2/openapi.yaml`.

## 14. Сайт editorstudio.ru

### Структура

| Адрес | Что там | Откуда берётся |
|---|---|---|
| `/` | стартовая страница | `site/` этого репозитория |
| `/metafora/` | консоль «Метафоры» | `static/` этого репозитория |
| `/doaj/` | DOAJ Metadata Studio | репозиторий [tsentavta/doajmds](https://github.com/tsentavta/doajmds) |

Сайт статический и работает на GitHub Pages без сервера. Оба API (DOAJ и «Метафора») принимают запросы прямо из браузера.

### Сборка

`tools/build_site.py` собирает всё в папку `_site/`:

- **Стартовая страница:** копирует `site/` в корень сайта.
- **Консоль:** копирует `static/` в `/metafora/`.
- **DOAJ:** копирует doajmds в `/doaj/`. doajmds рассчитан на корень своего домена, поэтому ссылки от корня (`/guides/`, `/en/`, `/favicon.svg`, `start_url` в manifest) переписываются на `/doaj/…`. Исходники (`tools/`, `guides-src/`), README, `robots.txt`, `sitemap.xml` и файл подтверждения Яндекса не копируются.
- **Проверка:** если после переписывания в doaj осталась ссылка от корня без `/doaj/`, сборка падает с ошибкой.

Собрать и посмотреть локально:

```bash
git clone https://github.com/tsentavta/doajmds.git ../doajmds
python tools/build_site.py --doaj ../doajmds --out _site
python -m http.server 8090 --directory _site
```

После этого откройте <http://127.0.0.1:8090>.

**Канонические адреса DOAJ.** По умолчанию страницы под `/doaj/` сохраняют `canonical` и `hreflang` на `https://doajmds.site/`. Для поисковиков это зеркало, и позиции doajmds.site не страдают. Чтобы основным адресом стал editorstudio.ru, добавьте к сборке ключ `--doaj-canonical` (в `.github/workflows/pages.yml`) и поставьте на doajmds.site ссылку или canonical на новый адрес.

### Публикация

Публикацией занимается `.github/workflows/pages.yml`. Сайт пересобирается:

- при каждом пуше в `main` этого репозитория;
- раз в сутки (в 03:17 UTC), чтобы подхватить изменения doajmds;
- вручную: Actions → «Сайт editorstudio.ru» → Run workflow.

Чтобы изменения doajmds попадали на сайт сразу, добавьте в doajmds шаг, который отправляет событие `doajmds-updated`. Для этого нужен токен с правом `repo` на editorstudio, сохранённый в secrets doajmds как `EDITORSTUDIO_TOKEN`:

```yaml
- run: gh api repos/tsentavta/editorstudio/dispatches -f event_type=doajmds-updated
  env:
    GH_TOKEN: ${{ secrets.EDITORSTUDIO_TOKEN }}
```

### Домен (настраивается один раз)

1. **GitHub.** Settings → Pages: в Source выбрать **GitHub Actions**, в Custom domain указать `editorstudio.ru`. Файл `CNAME` сборка кладёт сама.
2. **DNS у регистратора editorstudio.ru:**
